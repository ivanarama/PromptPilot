# Inbox: приём обращений из почты и Telegram → триаж → бэклог → исполнение

Статус: план, утверждён 2026-09-23.
Цель: любой запрос клиента (письмо или сообщение в ТГ) превращается в карточку
задачи с ТЗ, попадает в общий бэклог, исполняется назначенной моделью и
закрывается ответом в тот же канал — по согласию человека.

## Требования → механизм

| # | Требование | Механизм |
|---|---|---|
| а | Метка/пересылка → общий бэклог | Адаптеры приёма (IMAP-polling + ТГ-бот) нормализуют обращение в карточку = задача в PromptPilot с пермалинком источника |
| б | Триаж: проект + ТЗ | Одна дешёвая LLM-задача: каталог проектов на входе → проект/тип/приоритет + черновик ТЗ (Контекст / Что нужно / Критерий готовности / Открытые вопросы). Не уверен → кнопки выбора проекта человеку |
| б2 | Исполнитель + автоисполнение | Исполнитель = provider+model на карточке. Правило на проекте: авто-проекты (белый список типов + высокая уверенность триажа) сразу в очередь; остальные ждут тапа «Запустить». Предохранитель — бюджетный лимит |
| в | Ответ в тот же канал, по согласию | Карточка хранит канал+тред (пермалинк). После исполнения черновик ответа приходит человеку: ТГ-кнопки «Отправить / Править / Молчать»; почта — SMTP после тапа. Автоответ — только для явно разрешённых проектов |
| г | История | Задача хранит исходный текст, ТЗ, вердикт, лог исполнения + ссылку на отправленный ответ. Цепочка «письмо → ТЗ → прогон → ответ» восстанавливается по одной карточке |

## Архитектура

```
[Email IMAP]──┐
              ├─→ inbox-скрипт (нормализация) → триаж-задача (дешёвая модель)
[Telegram] ───┘            │                        │
                           │                 проект+ТЗ+уверенность
                           ▼                        ▼
                    карточка в очереди PromptPilot ◀─ человек (кнопки ТГ)
                           │
                    исполнитель (provider/model) → прогон → вердикт
                           │
                    черновик ответа → согласие → исходный канал
```

Ключевые поля карточки: `source` (email/telegram), `author`, `permalink`
(Message-ID+папка / ссылка на сообщение), `project`, `triage` (JSON: проект,
тип, приоритет, уверенность), `spec` (ТЗ), `reply_to`.

Каталог проектов: имя + 2–3 строки «что это», в конфиге inbox-скрипта.
Кейсы «человек выбрал проект вручную» дописываются в каталог как примеры.

## Приёмник почты (MVP — без внешних сервисов)

- Отдельный ящик только под задачи (не личный).
- IMAP-polling раз в 60с: непрочитанные → карточка → пометить прочитанным.
  Idempotency по Message-ID (не создавать дубликаты при рестарте).
- Вложения: сохранять в `~/.promptpilot/inbox/<id>/`, ссылку в карточку.
- Авторизация: пароль приложения (не основной пароль), хранится в `.env`.

Позже (этап 2): Cloudflare Email Worker или входящий webhook провайдера шлёт
POST прямо в PromptPilot API — polling исчезает.

## Приёмник Telegram (этап 2)

- Пересылка сообщения боту (бот видит forward-происхождение);
- хэштег `#задача` в чате с ботом;
- обработчик в существующем боте, тот же нормализатор, `source=telegram`.

## Этапы

### Этап 0 — ящик (сделать человеку)
- Есть домен на Cloudflare → включить Email Routing `tasks@<домен>` →
  пересылка в ящик с IMAP (бесплатно); позже Email Worker вместо polling.
- Нет домена → завести отдельный ящик Яндекс Mail или Gmail:
  включить 2FA, создать «пароль приложения», записать IMAP-хост/логин/пароль.

### Этап 1 — MVP на реальном письме (проверка ценности)

Статус: реализован 2026-09-23 (`scripts/inbox/`). Первый сквозной прогон успешен:
IMAP Mail.ru → нормализация → задача триажа в PromptPilot → ТЗ за 23.5с/$0.08.
1. Скрипт-приёмник (~150 строк): IMAP → карточка → POST в PromptPilot API
   (`source=email`, пермалинк, текст).
2. Триаж-задача: каталог проектов зашит в шаблон промпта; выход — JSON
   (проект, тип, приоритет, уверенность) + черновик ТЗ.
3. Карточка человеку в ТГ: ТЗ + кнопки «Запустить (модель X) / Сменить
   проект / Отклонить».
4. После исполнения — черновик ответа в ТГ; на MVP можно не отправлять,
   а только показывать: этого достаточно, чтобы оценить качество.

Критерии успеха на 5–10 реальных обращениях: проект определяется верно ≥ 80%,
ТЗ пригодно «как есть» без переписывания чаще чем нет, тап-подтверждение
не раздражает.

### Этап 2 — каналы и автоматизация

Статус: реализован 2026-09-23 (`scripts/inbox/inbox_bot.py`).
ТГ-карточки с кнопками (▶ Запустить / ✖ Отклонить), запуск исполнения в папке
проекта по кнопке, черновик ответа автору с отправкой по SMTP (In-Reply-To)
после тапа, авто-проекты (`"auto"` в projects.json: тип + уверенность,
AUTO_MAX_PER_DAY). Для кнопок нужен отдельный токен бота (INBOX_BOT_TOKEN,
создать у @BotFather) — чтобы не делить long-polling с основным ботом.

### Этап 3 — полное авто (осторожно)
- Автоответы в канал без тапа — только для явно разрешённых проектов и типов,
  с дневным лимитом и полной записью в журнал.

## Безопасность

- Пароль приложения ящика и SMTP — в `.env`, не в репозитории.
- Черновик ответа всегда человек-в-цикле, кроме явно разрешённых автопроектов.
- Ответ от имени человека — только через его подтверждение.

## Что нужно для старта этапа 1

1. IMAP: хост, логин, пароль приложения.
2. PromptPilot: адрес API (+ токен, если установлен).
3. `PP_TG_CHAT_ID` для карточек человеку.
4. Каталог проектов: минимум 2–3 проекта с описанием в одну-две строки.
5. Одно реальное письмо для первого прогона.
