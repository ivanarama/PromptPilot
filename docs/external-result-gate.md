# Проверка файлов внешнего исполнителя

Стандартный gate зарегистрированного MCP-проекта проверяет фактическую сдачу
текущего раунда, привязку к исполнителю, контрольные суммы и точный набор файлов.
Он читает SQLite в режиме read-only. Содержание отдельно оценивает проверяющий.
Автоматического применения файлов к рабочему репозиторию нет.

Ожидаемые файлы задаются в настройках проекта. Если нужны патч и отчёт, укажите
`changes.patch` и `RESULT.md`. В расширенном workflow JSON можно дополнительно
включить проверку применимости патча:

```json
{
  "external_result_policy": {
    "artifacts": ["changes.patch", "RESULT.md"],
    "text_artifacts": ["RESULT.md"],
    "patch": {
      "artifact": "changes.patch",
      "allowed_paths": ["README.md", "docs/"]
    }
  }
}
```

Путь с `/` на конце разрешает файлы внутри этого каталога. Другие значения
обозначают точные пути. Проверка текстового патча допускает изменения существующих
обычных файлов, ограничивает их размер и проверяет применение к индексу Git без
изменения файлов. Добавление, удаление, переименование, смена режима, символические
ссылки и бинарные патчи этим режимом не поддерживаются. До и после проверки HEAD
должен совпадать с базой раунда, а отслеживаемые файлы должны быть чистыми.

Успешный gate подтверждает получение и применимость предложенных файлов.
Приёмка содержания, тесты проекта, публикация PR и разрешение на слияние остаются
отдельными действиями. Если нужны проектные проверки, владелец задаёт их в
конфигурации процесса. MCP-клиент не может подменить эти команды.
