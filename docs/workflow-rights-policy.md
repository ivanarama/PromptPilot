# Описание прав в задании workflow

Нативные задачи planner, executor и reviewer получают блок `workflow-rights-v2`
из фактического поля `tasks.rights`. Он добавляется сервером после пользовательского
текста, шаблона роли и указаний этапа, перед заключительным контрактом ответа.
Собственный шаблон не может убрать эту доставку. Внешний исполнитель остаётся
внешним: текст не устанавливает ему права CLI.

Версия политики входит в input fingerprint новых нативных запусков. Уже
сохранённые fingerprints и контракт внешнего исполнителя не пересчитываются.

Словарь один: `none` — без инструментов, `read` — чтение без изменений, `write` —
правка файлов в рабочей папке без команд, `full` — инструменты в пределах полномочий
задания. Если `rights` отсутствует, блок честно указывает legacy и фактический
`skip_permissions`; новый ограниченный режим не выдумывается.

Этот блок объясняет настройку. Реальные ограничения и отказ неподдерживаемому
провайдеру по-прежнему обеспечивают CLI-адаптеры. Сторож остаётся отдельным
механизмом. Ни текст, ни `ELICIT`, ни ответ оператора не повышают `write` до `full`.
Командную проверку нужно передать оператору либо утверждённому gate.

Версия v2 также описывает структурированный вопрос executor/reviewer: формат,
привязка к текущему запуску и ответ — в [контракте ELICIT](145-bound-elicitation.md).
Ответ сохраняется как указание для следующего запуска и не меняет права, не
исполняет запрошенное действие и не запускает продолжение автоматически.
Контракт исполнимых acceptance gates поставляется отдельным срезом #145.
Описание прав и вопросы не являются ОС-песочницей.
