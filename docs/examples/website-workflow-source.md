# Пример: заявки сайта и процессы PromptPilot

Это необязательная схема интеграции веб-приложения. Название конкретного
развёртывания, например NewIS, не является типом источника, зависимостью
PromptPilot или условием работы общего списка.

Предположим, сайт принимает заявки, согласует их с человеком и только после
подтверждения конкретного запуска создаёт Workflow в своём экземпляре PromptPilot.
В этом случае владелец общего интерфейса может зарегистрировать этот экземпляр
как обычный источник типа PromptPilot:

```json
{
  "version": 1,
  "sources": [
    {
      "id": "website-worker",
      "label": "Процессы сайта",
      "base_url": "https://website-worker.example",
      "token_env": "REMOTE_PP_TOKEN"
    }
  ]
}
```

Адрес и имя переменной — примеры. Сам файл не создаёт сетевой доступ, не выдаёт
права сайту и не запускает его процессы. Применяются общие
[правила регистрации и доступа](../TASK_SOURCES.md).

## Что появится в списке

После создания Workflow новый API списка задач отдаёт одну карточку процесса.
Его внутренние попытки исполнителя, проверки и ревизии остаются в истории той же
карточки. При нескольких источниках идентификатор содержит ID источника, поэтому
совпадающие локальные ID не смешиваются.

Если источник работает на старой версии API и `/api/task-feed` отвечает 404,
агрегатор читает `/api/workflows` и помечает источник как частичный. Это означает
ограничение контракта чтения: доступны Workflow, но нет нового бизнес-представления
всех отдельных задач. Нулевой список Workflow не доказывает отсутствие заявок на
сайте. Ошибка доступа или timeout также не означает пустой список.

## Заявки до запуска: контракт request

Письмо, новая заявка и согласование до запуска ещё могут не иметь Workflow.
Для их отображения сайт реализует явно разрешённый read model с отдельным
read-only токеном, а владелец регистрирует HTTPS-адрес сайта как источник.
Агрегатор не читает почту или внутреннюю базу сайта.

`GET /api/task-feed?local_only=true&limit=100&offset=0` возвращает:

```json
{
  "total": 1,
  "items": [{
    "source_id": "local",
    "kind": "request",
    "object_id": "order_123",
    "title": "Доработка обработки выгрузки",
    "status": "needs_attention",
    "status_label": "Ошибка приёма",
    "status_reason": "Файл settings.xyz: неподдерживаемый формат.",
    "source_path": "/orders/order_123/"
  }]
}
```

`object_id` — стабильный ID заявки, до 128 латинских букв, цифр, `_` и `-`.
Он остаётся прежним при планировании, согласовании, выполнении и доработках.
Статусы: `queued`, `active`, `blocked`, `needs_attention`, `completed`, `cancelled`.
Карточка читается через `GET /api/task-feed/local/request/order_123` и возвращает
`item`, `history: {runs: [], events: []}`, `result` и `artifacts`.

Необязательный `source_path` — абсолютный путь на зарегистрированном сайте,
состоящий из `/`, латинских букв, цифр, `_` и `-`, без двойного `/`.
Агрегатор сам строит ссылку на origin источника. Произвольный peer URL, userinfo,
query, fragment и escape-последовательности не принимаются. Переход открывает
сайт с обычной авторизацией; токен источника в браузер не передаётся.

Чтобы одна заявка оставалась одной строкой, сайт отвечает за её полный жизненный
цикл и историю; его исполнительный экземпляр PromptPilot не подключают вторым
источником тех же процессов. Общий список не угадывает связи по заголовку.

Повторный запуск заявки может создать другой Workflow; при контракте `request`
он остаётся внутри истории той же заявки со стабильным ID.

Чтение источника не объединяет базы, очереди, credentials и аренды исполнителей.
Оно не запускает работу, не даёт приложению право на публикацию и не заменяет
проверки и приёмку результата. Этот пример не утверждает, что конкретный сайт
уже подключён или поддерживает все перечисленные состояния.
