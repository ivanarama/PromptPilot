# Материалы для публикации на Инфостарте

## Основной заголовок

Очередь не уменьшается. Как с нуля собрать GitHub-конвейер ИИ-агентов и найти бутылочное горлышко

## Альтернативные заголовки

1. TRIAGE → FIX → REVIEW → MERGE: практический конвейер ИИ-агентов для GitHub
2. Почему ИИ десять раз ревьюит один старый PR и как это увидеть за пять минут
3. Backlog тот же, токены потрачены: строим наблюдаемый pipeline сопровождения

## Анонс

Пошагово собираем для нового GitHub-репозитория постоянный конвейер
TRIAGE/FIX/REVIEW/MERGE: устанавливаем PromptPilot, вводим человеческие gates,
добавляем обезличенные skill-контракты, создаём расписание и подключаем
безтокенную аналитику. На примере очереди из 24 PR разбираем, как отличить
обычное бутылочное горлышко REVIEW от зацикливания на одних и тех же старых PR.

## Редакторские ограничения

- Не называть dashboard «ИИ-аналитикой»: метрики считаются без LLM.
- Не обещать точную дату очистки: ETA приблизительна и не учитывает новый вход.
- `reviewed` не равно разрешению на merge; `ship` ставит человек.
- Starter kit является безопасной основой, но требует адаптации проверок и
  branch protection конкретного репозитория.
- Не смешивать maintenance pipeline с конечным Workflow Orchestrator.
