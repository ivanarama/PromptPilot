# Подключить агента к PromptPilot

После подключения можно написать в своём клиенте: «Поставь задачу по этой ссылке
в проекте `my-project` через PromptPilot и пришли ссылку на карточку». Дальнейшее
состояние задачи доступно через MCP и в общем списке PromptPilot. Передавать между
чатами папки с заданиями не требуется.

## Один раз настроить проект

Откройте **Настройки → Подключения агентов** в своём PromptPilot.
Сервер должен быть запущен с настроенным `PP_API_TOKEN`; войдите в интерфейс как
владелец. Если токен API пока не задан, сначала настройте его в окружении сервера
по `.env.example` и перезапустите свой сервер. Пароль владельца и отдельный токен
MCP-подключения — разные учётные данные: клиенту выдаётся только второй.

1. Зарегистрируйте проект: ID, понятное название и путь к локальному Git-репозиторию
   **на компьютере PromptPilot**. GitHub URL нужен, если будете передавать issues
   по ссылке. Для задачи с текстовой целью GitHub необязателен.
2. Выберите внешний клиент-исполнитель и проверяющего провайдера. Начальные
   значения — `zcode` и `codex`; это разные роли, а не ограничение на модель.
3. Укажите файлы результата и доступный агенту контекст. По умолчанию ожидается
   `RESULT.md`: стандартная проверка подтверждает получение файлов и их хеши,
   а содержимое оценивает отдельный проверяющий. Начальный список
   чтения — `README.md` и `AGENTS.md`. Можно указать точный файл или каталог с `/`
   на конце; это не glob и не разрешение изменять файлы.
4. При необходимости сохраните переиспользуемый workflow JSON в расширенных
   настройках. Проверки, права и согласования задаёт владелец проекта. Входящий
   план требует его подтверждения; MCP-клиент не может подменить эту политику.
   Пустой JSON `{}` использует встроенную проверку результатов. Для своего проекта
   можно добавить тесты и правила применения патча.
5. Сохраните проект. Создайте подключение, отметив проекты, к которым ему нужен
   доступ. Оно сможет читать задачи этих проектов, в том числе созданные другим
   подключённым клиентом того же владельца.

Создание подключения выдаёт токен **один раз**. В этом же окне скопируйте HTTP MCP
JSON или Codex TOML в приватные настройки клиента. После закрытия окно больше не
покажет этот токен. В списке остаётся подключение; его доступ можно отозвать,
сохранив задачи. При потере токена создайте новое подключение и отзовите старое.

## Настроить клиент

Адрес берётся из открытого вами PromptPilot, например
`https://pilot.example/api/agents/mcp`. Другой компьютер должен иметь доступ к
этому адресу. `localhost` указывает на компьютер самого клиента, поэтому для
удалённого подключения откройте PromptPilot по доступному ему адресу. Используйте
HTTPS для передачи токена между компьютерами.

- **ZCode:** Settings → MCP Servers → New MCP Server → HTTP. Укажите адрес и
  заголовок `Authorization: Bearer <токен>`, либо вставьте скопированный JSON в
  Full configuration mode. ZCode документирует HTTP, заголовки и импорт
  `mcpServers`. [Официальная инструкция](https://zcode.z.ai/en/docs/mcp-services).
- **Claude Code:** скопированный HTTP JSON подходит для MCP-конфигурации клиента.
  Также доступна команда
  `claude mcp add --transport http promptpilot <адрес> --header "Authorization: Bearer <токен>"`.
  Выберите нужный scope конфигурации. [Официальная инструкция](https://code.claude.com/docs/en/mcp).
- **Codex:** добавьте скопированный TOML в `~/.codex/config.toml`. Он использует
  стандартные `url` и `http_headers`. Вместо сохранённого заголовка можно задать
  `bearer_token_env_var`, обеспечив доступ к этой переменной в каждом запуске
  клиента. [Официальная инструкция](https://developers.openai.com/codex/mcp).

Конфигурация с заголовком содержит секрет: храните её в настройках пользователя,
не в публичном репозитории. Сохранённое подключение используется и в следующих
сессиях; повторно копировать токен в каждый запрос агенту не нужно. Переподключите
MCP-сервер в клиенте, если он ещё не загрузил инструменты.

Другие клиенты тоже могут подключиться, если поддерживают HTTP MCP с Bearer-заголовком;
формат их файла настроек может отличаться. Модель выбирается в клиенте и должна
уметь вызывать инструменты через него. Это не обещание совместимости со всеми
моделями и не перенос подписки, оплаты или лимитов между приложениями.

## Как поставить задачу

После обнаружения инструментов PromptPilot достаточно обычного запроса:

> В проекте my-project разберись с заявкой по этой ссылке: <URL заявки>.
> Создай задачу в PromptPilot, покажи карточку и затем проверь её состояние.

Агент увидит разрешённые проекты, их назначение и доступный контекст. Локальные
пути, настройки провайдеров и секреты не нужно включать в запрос. Статус задачи
сохраняется на стороне PromptPilot и доступен следующей сессии клиента.

Перед выполнением подтвердите предложенный план в карточке PromptPilot. Если
клиент передал только цель, предложение содержит один этап. Клиент также может
передать план из нескольких этапов; решение о запуске остаётся за владельцем.

Это подключение управляет постановкой задач и чтением состояния. Если workflow
использует внешнего исполнителя, его уже существующее подключение настраивается
отдельно: MCP-токен не заменяет токен исполнителя и не делает текущий чат
исполнителем автоматически. Проверяющий и обязательные проверки работают по
настройкам зарегистрированного проекта.
