# Где сейчас задача

В карточке workflow верхний блок показывает этап, раунд, ответственного,
текущее ожидание и следующее действие. Полное задание находится в раскрываемом
разделе. История раундов и технический журнал сохранены ниже.

**Этап** — часть плана. **Раунд** — очередная попытка выполнить этот этап.
Возврат результата открывает следующий раунд той же задачи, а не новую задачу.

Лента «План → Исполнение → Проверка файлов → Ревью → Готово» относится к
текущему раунду. Процент готовности плана учитывает только завершённые этапы.

Для внешнего MCP-исполнителя различаются состояния:

- Задание доступно, но ещё не забрано.
- Исполнитель забрал задание, ожидается результат.
- Сдача началась, подтверждение ещё не получено.
- Состояние сдачи требует сверки.

Получение задания — сигнал подключения. Оно не подтверждает фактический запуск
модели и не означает приёмку результата.

## Почему результат вернулся

Возврат остаётся видимым при подготовке следующей сдачи. Для несовпадения имён
показываются ожидаемые и полученные пути. Например, файл может храниться у
исполнителя в `.pp-run/RESULT.md`, а поле `path` сдачи должно соответствовать
объявленному имени `RESULT.md`.

Новые проверки возвращают ограниченный структурированный код ошибки без
текста внутренних исключений. Исторический отказ с общей причиной можно
дополнить **сверкой по текущим правилам**: она явно подписана, проверяет
квитанцию и хеши файлов, не переписывает старое событие и не переигрывает gate.

После успешной технической проверки и перехода к ревью старая причина
возврата остаётся в истории, а верхний блок отражает текущее состояние.

`GET /api/workflows/{id}/progress` — проекция для владельца. Чтение не создаёт
заданий, не забирает их, не меняет этапы, решения и полномочия. Версия проекции
проверяется вместе с версией workflow, чтобы поздний ответ не подменял
состояние другой карточки.

## Повторная проверка очереди в ZCode

Совместимый клиент выбирается отдельно от модели. В ZCode можно использовать
активную сессию с инструкцией опрашивать MCP либо повторный запуск через
**Automations → Create scheduled task**. Документированные расписания начинаются
с часовых интервалов. Для короткого опроса подходит активная сессия; настройки
подтверждений сами по себе повторный опрос не включают.

Официальные инструкции: [Automations](https://zcode.z.ai/en/docs/automations),
[Goal Mode](https://zcode.z.ai/en/docs/goal),
[Execution Modes](https://zcode.z.ai/en/docs/agents#execution-modes).
